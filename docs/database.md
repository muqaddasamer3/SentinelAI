# SentinelAI Database Design

## Project

**Project Name:** SentinelAI – Smart Incident Response & Safety Monitoring System

This document defines the database architecture for **SentinelAI**. It serves as the reference for the AI Pipeline, FastAPI Backend, Frontend Dashboard, and Database Development.

---

## Database

| Property | Value |
| -------- | ----- |
| Database Engine | PostgreSQL |
| Hosting | Supabase |
| ORM | SQLAlchemy |
| Migration Tool | Alembic |
| Primary Key Type | UUID |

---

## Database Purpose

The database stores:

- Registered CCTV cameras
- Detected persons
- Tracking history
- AI-generated incidents
- Alert information
- Dashboard users

The AI pipeline generates tracking information, the backend stores it, and the frontend displays it.

## Database Tables

### 1. Cameras

#### Purpose — Cameras

Stores information about every CCTV camera.

| Column | Type | Description |
| -------- | -------- | -------- |
| id | UUID (PK) | Primary Key |
| camera_id | String (Unique) | Camera Identifier |
| camera_name | String | Camera Name |
| location | String | Camera Location |
| status | String | Active / Offline |
| created_at | Timestamp | Record Creation Time |

---

### 2. Persons

#### Purpose — Persons

Stores every unique person detected by the AI system.

| Column | Type | Description |
| -------- | -------- | -------- |
| id | UUID (PK) | Primary Key |
| person_code | String (Unique) | Example: P001 |
| face_embedding | Binary | InsightFace Embedding |
| first_seen | Timestamp | First Detection Time |
| created_at | Timestamp | Record Creation Time |

#### Notes

- `person_code` example: **P001**
- `face_embedding` is generated by **InsightFace**

---

### 3. Tracking Logs

#### Purpose — Tracking Logs

Stores every tracking event detected by the AI pipeline.

| Column | Type | Description |
| -------- | -------- | -------- |
| id | UUID (PK) | Primary Key |
| person_id | UUID (FK) | References Persons |
| camera_id | UUID (FK) | References Cameras |
| entry_time | Timestamp | Entry Time |
| exit_time | Timestamp | Exit Time |
| event_type | String | Entry / Exit / Detected |
| zone | String | Camera Zone |
| confidence | Float | Detection Confidence |
| face_matched | Boolean | Face Recognition Result |
| clothing_color | String | Clothing Color |
| snapshot_url | String | Stored Image URL |
| created_at | Timestamp | Record Creation Time |

#### Example Event Types

- detected
- entry
- exit

#### Example Zones

- Entrance
- Lobby
- Parking
- Restricted Area

---

### 4. Incidents

#### Purpose — Incidents

Stores incident summaries generated by Gemma 4.

| Column | Type | Description |
| -------- | -------- | -------- |
| id | UUID (PK) | Primary Key |
| tracking_log_id | UUID (FK) | References Tracking Logs |
| person_id | UUID (FK) | References Persons |
| camera_id | UUID (FK) | References Cameras |
| incident_type | String | Incident Category |
| summary | Text | Gemma Generated Summary |
| severity | String | Low / Medium / High / Critical |
| timestamp | Timestamp | Incident Time |
| created_at | Timestamp | Record Creation Time |

#### Example Incident Types

- Loitering
- Intrusion
- Suspicious Activity
- Unauthorized Entry
- Crowd Formation

#### Severity Levels

- Low
- Medium
- High
- Critical

---

### 5. Alerts

#### Purpose — Alerts

Stores alerts generated after incidents.

| Column | Type | Description |
| -------- | -------- | -------- |
| id | UUID (PK) | Primary Key |
| incident_id | UUID (FK) | References Incidents |
| recipient | String | Receiver |
| status | String | Pending / Sent / Failed |
| sent_at | Timestamp | Alert Sent Time |
| created_at | Timestamp | Record Creation Time |

#### Recipients

- Security Guard
- Administrator
- Control Room

---

### 6. Users

#### Purpose — Users

Stores dashboard users.

| Column | Type | Description |
| -------- | -------- | -------- |
| id | UUID (PK) | Primary Key |
| username | String | Username |
| email | String | Email Address |
| password_hash | String | Encrypted Password |
| role | String | User Role |
| created_at | Timestamp | Record Creation Time |

#### Example Roles

- Admin
- Security Officer
- Supervisor

## Database Relationships

```text
Camera (1)
     │
     └──────────────┐
                    │
               Tracking Logs (*)
                    │
                    │
Person (1) ─────────┘
                    │
                    ▼
               Incident (0..1)
                    │
                    ▼
                Alerts (*)
```

Relationship Summary

| Parent | Child | Relationship |
| -------- | -------- | -------- |
| Camera | Tracking Logs | One-to-Many |
| Person | Tracking Logs | One-to-Many |
| Tracking Log | Incident | One-to-One (Optional) |
| Incident | Alerts | One-to-Many |

## Security Considerations

- Database hosted on Supabase
- Credentials stored in `.env`
- `.env` is ignored by Git
- UUID used as primary keys
- Passwords stored as hashed values only
- Database access controlled through Supabase authentication and Row Level Security (RLS) if enabled
